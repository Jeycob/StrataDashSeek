HOST application preview controller (source integration)

Purpose and default

The HOST composition offers project_preview independently of Apps/VM enablement.
It is disabled without a valid explicit hostPreview configuration, Linux
little-endian/getuid capability and the actual app-owned range subprocess
provider below. An unavailable configuration returns unavailable
without creating a connector, relay or broker. Isolated-guest composition never
constructs this HOST controller and has no fallback to a HOST process.

Only the trusted apps-config.json file read by workspace/plugin.mjs supplies:

  "hostPreview": {
    "enabled": true,
    "ownerOrigin": "https://EXISTING-OWNER.ts.net",
    "endpoints": [
      {"origin":"https://EXISTING-OWNER.ts.net:8443","listenerPort":18190}
    ]
  }

This is a configuration example, not a provisioned endpoint. Root must select
the actual unused private loopback listener and arrange HTTPS to it. The public
HTTPS port and loopback listenerPort need not match. No domain, certificate,
Tailscale, Serve/Funnel, firewall or runtime configuration is changed by this
source. Origin and listener collisions with configured editor endpoints disable
preview custody; malformed editor endpoints also fail closed. Every origin must
differ from ownerOrigin. HTTPS on the same hostname at a different explicit port
is allowed with the broker's cookie/fetch-metadata/origin/Host defenses below.

Origins persist by canonical project-root hash in manager.root/
host-preview-origins.json, separately from editor-origins.json. An allocation is
never recycled to another project, even after a lease closes or a session ends.
Retain this private state across upgrades; do not delete it to increase capacity.
Exhaustion or incompatible origin configuration refuses a new preview. Only one
active preview lease exists per project session. Origin capacity is finite.

Application and model flow

Start the application through ordinary project_exec (or managed bash) with
run_in_background:true, listening on the project's assigned DSH_APP_PORT / first
record port. The public command schema and background result remain unchanged.
Only explicitly enabled, supported HOST preview composition prepares the
actual sandbox argv and adds custody when it selects the installed Landlock
launcher (identified by the SDK's exported launcherPath). This does not execute
the target or override the SDK's selection/probes. A bwrap/other/unknown backend
keeps ordinary background execution without custody, and preview refuses that
job. Restart also rechecks this before admitting its captured specification.
There is no
model option to request custody, choose a PID, substitute an executor or bypass
the confined SDK process policy.

  project_preview {"operation":"open","jobId":"OWN-SDK-JOB-ID"}
  project_preview {"operation":"status"}
  project_preview {"operation":"close"}

The actual executing SDK agent owns the job and preview. Root and child agents
cannot open, observe or close each other's lease. The model cannot supply a
session, host, target port, PID, root, URL, generation or command. Project,
workspace membership, live access policy, canonical root/device/inode and unique
assigned ports are derived and rechecked from the real manager/SDK state.

Open probes attribution with zero HTTP bytes, then creates a private generated
UDS/named-pipe relay and a loopback broker. Every broker HTTP connection requires
a fresh verified same-socket connector result before any HTTP bytes cross the
relay. Attribution refusal closes that connection and never kills or adopts the
foreign listener. No permissive proxy or direct-port fallback exists.

Wrapper custody does not prove that the application's listen() has completed.
The connector may retry only a refused pre-connect socket after its actual
zero-write close, with the same target, live custody/anchor and original bounded
deadline. It never repeats the application command, resets expiry or redials
after an established connection's attribution fails. See HOST_PEER_CONNECTOR.

The normal tool renderer provides an Open application preview Markdown link;
no Native bundle change is needed. Open again with the same own job ID for a
fresh one-use link before expiry. Status contains no new bearer grant. The
previewId identifies a stable broker lease; generation identifies the current
captured backend wrapper and changes on successful restart.

Owner control and exact restart

Trusted owner-control status additionally includes correlation with version,
sessionId/ownerAgentId/jobId/previewId/current generation/original expiresAt and
two call records: originalCall and producerCall. Each retains the actual SDK
execution callId, rootCallId and toolName. The first admission record stays
fixed across restart; the current producer record changes immediately on exact
new SDK admission. Call evidence is retained privately with that own producer,
not inferred from native JobView or rendered job text. Missing/non-printable/
over256-byte identifiers are null (unknown). Correlation is evidence only: no
caller fields, selector or authority are added. Model tool open/status/close
and owner open/restart/close outputs do not expose this status-only record.
An observer must bind the complete ready-state fingerprint and both real
history identifiers; absent/mismatched correlation cannot excuse unsettled work.

Owner restart failures return {code,diagnostic}; owner status retains the same
lastRestartFailure. The bounded diagnostic records observedAt and phase
(stop-old/context/admission/custody/peer-probe/post-probe), safe error code and,
when available, peer phase/dial count/established/last connect code. It includes
no raw exception message, stderr, PID, root or credentials. Model status does
not expose it. This distinguishes an old-range stop failure from a new app's
listen/proof failure, including after exact new-producer cleanup. Preserve the
actual non200 body before archiving. A later delayed-listen reproduction proves
that source race exists, not that it caused an earlier attempt whose code/body
was not retained. Restart receipts remain idempotent; diagnostics cause no retry.

The existing owner-Peer authenticated connection service registers exactly
POST /api/workbench/preview with buffered JSON at most2048 bytes and a second
sameRequestOrigin mutation fence. The public internet broker has no control API.
Only the trusted owner route accepts a session selector and restart:

  {"operation":"open","sessionId":"...","jobId":"..."}
  {"operation":"status","sessionId":"..."}
  {"operation":"close","sessionId":"..."}
  {"operation":"restart","sessionId":"...","previewId":"...",
   "generation":"...","requestId":"bounded-unique-id"}

There are no replacement command/host/port/PID/root fields. A private opaque
seed retains the originally admitted command arguments, owner, resolved policy,
environment, paths and deadline. Restart refreshes real policy and requires the
same resolved specification. It first revokes the old relay target and awaits
the exact old SDK producer's done, then makes one new admission through the real
SDK tools guard/approval/heavy-admission pipeline with a one-use private ticket.
Ordinary tool resolution cannot obtain project_preview_restart. The shared
heavy permit remains retained until the new producer actually settles.

Reopen a saved result after expiry

For a verified preview initially opened by the project conversation itself, the
controller saves its original startup arguments and a digest of the resolved
execution specification in private workbench state. It records settlement only
after the exact producer ends. Owner status includes an optional
{result:{id,canReopen}}. A connected owner can explicitly request
{"operation":"reopen","sessionId":"...","resultId":"..."} when canReopen is true.
The app starts from the retained project through the existing SDK admission
pipeline, with current policy and the saved specification checked before launch.
Success returns ready, a new job and preview identity, a new bounded lifetime
and one-use link at the existing project origin. No prompt is sent. Completion
of this owner-started job is collected in job history without waking the model.

Refresh status on a stale result or uncertain response. Each result ID admits
at most one reopen attempt. For a ready preview, the existing open operation
with its current jobId issues another one-use link within its current lifetime.
An unknown settlement or changed project context can prevent reopening.
Projects with no saved preview are still available through their existing files.
GET /api/workbench/download?sessionId=...&path=... downloads a relative project
file up to 10 MiB through the authenticated owner connection.

Up to16 restart request IDs are retained for idempotent results; a repeated ID
returns the same operation, and a new stale generation refuses. A new producer
is recorded immediately on SDK admission, before its custody acknowledgment,
so a lost acknowledgment or cancellation can stop that exact new producer.
Unknown old settlement blocks restart without a new start. Refusal, abort or
proof failure never triggers a blind retry. Successful restart preserves the
origin, broker lease/cookie, and original expiry; its new job deadline cannot
extend the first admission. Close, archive, agent disposal, policy/context
revocation, producer completion, runtime disposal and expiry revoke the broker
and relay. Lifecycle cleanup uses only retained SDK-owned jobs.

workSettled:true means this preview's retained SDK producer done was observed
through the actual whole-range provider described below;
it never means every Native/background job in the conversation has stopped.
No-lease close/status is scoped to this preview. An unsuccessful open leaves the
original owned application job available for job_output/job_kill. A cleanup
timeout reports blocked/workSettled:false rather than asserting settlement.

Pinned SDK whole-range contract and cold-start registration

Stock dsh-bash-local/SandboxBashExecutor exposes ShellExecution.done/result()
only for direct command outcome plus bounded pipe drain. ShellExecution has no
waitForExit/raw provider handle. Its kill() stops calling the provider once the
direct outcome has changed status. Those facts alone cannot prove surviving
descendants exited and must not authorize a restart or settled-work claim.

The supported lower-level SubprocessHandle contract has terminate() paired with
waitForExit(signal): true proves its documented managed range is empty, false
means the caller signal aborted first, and rejection means observation failed.
workspace/owned-range-subprocess.mjs extends the ACTUAL pinned
LocalSubprocessRuntime and calls super.spawn(spec) unchanged. It delegates the
same streams/control/collection and bound terminate/waitForExit. The SDK retains
and disposes the ORIGINAL handle; inherited terminal/PTY behavior is unchanged.

Its returned done first reflects original.done (including failure), THEN calls
original.waitForExit(), and publishes the original outcome/error only after
strict true. No eager/parallel range observation is introduced: the SDK's
SystemdScopeOwner startup can race an early not-found observation. If range
observation is missing, false or throws, the adapter attempts only its exact
original terminate, emits one constant HOMEAI_RANGE_EXIT_UNOBSERVABLE warning,
and keeps done pending. Rejecting then would let Bash convert unknown range
state into fulfilled done/killed. Pending keeps the producer and heavy permit
retained, makes bounded preview cleanup blocked, and requires operator action;
it never fabricates settlement or starts a replacement. Direct provider failure
is rethrown only after verified range absence. Logging cannot alter this fence.

workspace/install.cjs deterministically disables the stock id=subprocess entry
and inserts exactly one cloud-owned-range-subprocess provider at
file:///data/harness/app/workspace/owned-range-subprocess.mjs. SDK patches treat
name as a selector guard, so an attempted in-place name change is unsupported.
Only one provider is active; no active service or SDK file is mutated.
Unknown/duplicate profile overrides refuse installation. The isolated profile
projector allows only this exact reviewed substitution and rewrites it to the
bound release path. Workspace cold-start injection declares subprocess and
sandbox. If the original stock provider remains installed, preview capability
is unavailable; a config flag cannot claim the private provider provenance.
Root must apply the profile change and cold restart through its authorized
release process before claiming whole-range preview/cleanup qualification.

The managed range is still the selected SDK provider's documented range. Native
systemd/Job containment and weaker process-tree/group fallback are not equal:
SDK fallback expressly cannot guarantee descendants that escape its group or
direct-parent tree. The adapter adds no process discovery, PID adoption,
signalling algorithm or stronger kernel containment claim.

Browser boundary and supported first unit

The broker reuses editor primitives with purpose=preview, /__preview controls,
and __Secure-homeai-preview-<origin-hash> HttpOnly Secure SameSite=Strict cookies.
Editor or Native owner cookies do not authorize it. Cookies alone cannot
separate ports: exact Host, Origin and browser fetch metadata are checked before
forwarding; sibling no-cors subresources are refused. Bootstrap grants are
one-use, short lived and capped. Expiry never renews the producer lifetime.

Cookie, Authorization, proxy/forwarded/Native/Tailscale identity headers are
removed upstream. Upstream Set-Cookie, CORS and Service-Worker-Allowed are
removed; response security headers and same-origin redirect checks apply.
App-owned cookie/Bearer authentication is therefore not supported by this first
unit. It supports ordinary HTML/assets and relative HTTP fetch APIs, including
PATCH/DELETE, error statuses/JSON and attachment bytes/filename headers. WebSocket
upgrades are explicitly refused for preview (existing editor WS is unchanged).
The UI must show genuine unavailable/error output, not claim preview readiness
merely because an app job ID exists.

Qualification boundary

HOST_PEER_CONNECTOR.txt describes the unchanged connector's bounds: Linux
procfs, actual UID, same PID/network namespace, exact accepted reverse TCP
four-tuple fd within the captured wrapper descendant graph, repeated bounded
snapshots and zero early bytes. This is snapshot attribution, not atomic or
exclusive kernel ownership. Unsupported namespaces (including a separate bwrap
PID namespace) refuse; platform capability alone does not prove an admissible
backend. There is no inference that bwrap behaves like Landlock.

Source tests use actual pinned SDK registration/jobs/pipeline/OutputCollector
with mocked subprocess handles. Separate tests use synthetic loopback HTTP/TCP
servers and real brokers/private relays with explicitly mocked attribution.
They prove source composition and refusal behavior, not real application,
kernel, TLS/browser, UID1001 or deployed owner-Peer acceptance. Root owns those
runtime qualifications, signed integration and configuration. The prepared
owned-range-linux.test.mjs requires explicit operator selection and a fresh
canonical non-writable-by-others /var/lib/homeai-owned-range-fixture-* directory
owned by its executing UID/GID with mode0700 and a12-character alphanumeric
suffix. The fixture creates and removes only its fresh verified run-* child;
after actual fixture exit Root removes the now-empty outer with rmdir. It
redirects the synthetic descendant's pipes so
the wrapper can exit, verifies that the job/permit remain held, then uses only
exact owned stop and observes its TERM trap and eventual range exit. B has not
executed this fixture. Live preview
acceptance and the frozen paired benchmark remain separate, unclaimed work.

Optional guest snapshot renderer

In host-compat, the trusted Apps configuration may select a guest renderer with
hostPreviewRenderer containing port, serverName and instance. The port belongs
to a reserved host loopback QEMU forward to the same port on guest 10.0.2.15.
The name is the guest certificate SAN under preview.homeai.invalid. The
instance is the guest kernel boot UUID, observed independently by the operator.
Keep the original preview origin and producer custody in Native.

Install the approved source files workspace/preview-guest-worker.mjs,
workspace/preview-guest-renderer.mjs, workspace/preview-snapshot.mjs,
workspace/source-private.cjs and development/versions.json with their relative
paths under one read-only guest root. Run the worker's Node entry point with
the port as its sole argument under a dedicated non-root guest identity. Use
the pinned Playwright toolchain under /opt/playwright and a guest kernel that
actually runs Chromium with chromiumSandbox enabled. Restrict the guest service
to the private transport and provide its own scratch space. Keep project
mounts, project environment, Docker control and host networking privileges
outside the renderer's scope. Provision the VM and worker before selection
so requests stay within the existing snapshot deadline.

Use a dedicated CA for this transport. Native reads ca.crt, client.crt and
client.key from /data/harness/secrets/preview-renderer. The worker reads ca.crt,
server.crt and server.key from /run/homeai-preview-renderer inside the guest.
Give each process its own mode 0700 credential directory and mode 0600 files.
Update the trusted instance binding when the VM boots again. The worker's
mTLS exchange carries the requested viewport, route, scroll and invocation
binding. Native serves the bounded asset reads from its own preview socket.
The binding retains Native's absolute owner deadline. After mTLS completes,
Native sends a fresh positive remaining budgetMs, capped at10000. The worker
uses that relative budget with its own timeout; it does not compare the two
machines' wall clocks. The client and worker must use this same frame schema.

The local Linux fixture uses a separate worker process, mTLS and real sandboxed
Chromium. For Vast acceptance, exercise the same mobile selection with the
actual guest UID, pinned browser, private forward and bound boot UUID. Repeat
with a stale generation and after closing the preview in another tab.
