# Reproducible source and UI checks

The GitHub workflow checks one exact commit on disposable Ubuntu 24.04 with
Node 24.22.1, Python 3.12.12, the production SDK lock, Web Push 3.6.7, and isolated
Playwright 1.65.1 / Wrangler 4.162.0 tooling. Test tooling has its own package lock;
it is not installed into the production runtime. All four official Actions
are pinned to full commit IDs. The workflow neither deploys nor uses production
credentials. Its successful result is not live production acceptance.

Pushes to `main`, `fix/**`, and `codex/**` run the same gate. This lets the
integration owner validate a normal Codex branch through an authorized Git push;
workflow dispatch and pull requests remain available.

## What runs

`development/release-ci.mjs` inventories Git-tracked and nonignored untracked
test sources, including development helpers' tests, Python names with both
hyphens and underscores, explicit Linux checks and the actual local workerd
restart check. Test discovery follows no links. New standalone checkers require
classification rather than being silently omitted or accidentally executed
against a live host.

Required suites run in their own bounded processes, two at a time. Each must
exit successfully and report a positive executed-test count. The actual local
workerd check instead must report its real engine and completed restart proof.
Python is executed directly per file, so hyphenated test filenames cannot
disappear through unittest discovery conventions. Linux metadata/two-UID
fixtures need root and run under sudo only on the disposable runner. The gate
refuses a host containing the production Harness guard path.

The real firewall fixture has a dedicated Node test wrapper. It generates the
current worker rules and starts the packet checks with `unshare --net`; the
Python fixture refuses the host namespace. The wrapper requires positive
results for bridge/control denial, pre-existing connections, previews, DNS/DHCP
and idempotence. Ubuntu's `iptables`, `iproute2` and `util-linux` are test
prerequisites, with installed versions recorded. OpenSSL and ripgrep are also
installed explicitly for actual editor certificate and isolated file-tool
fixtures. `HARNESS_FIREWALL_TOOLS` may
select an explicitly prepared local tools directory. Missing tools or namespace
support fail the required check; the raw Python helper is not run a second time
without its required arguments.

Native SDK tests receive the pinned CLI explicitly. Both source fixtures and
the literal distributed UI are exercised by existing browser suites. The gate
also executes the real UI builder in a temporary source replica and compares
the generated bytes with the committed bundle; it does not overwrite the
checkout. The Worker is compiled with a dry-run, never uploaded. Its compiled
files are included in the evidence with hashes.

The test environment explicitly excludes account, model and provider keys.
Default service writes go to a new private temporary root. All local test data
is synthetic, and existing-host smoke/admission scripts are never invoked by
this workflow. Those scripts remain in the inventory as unrunnable outside CI,
with their required environment explained. Historical challenge fixtures are
separately classified outside the production infrastructure gate, not counted
as passing or erased. Actual hardware/model tasks remain separate work.

## Evidence semantics

Artifacts contain the complete inventory, one bounded log per executed suite,
optional Native/editor screenshots, bundle reproduction hashes, compiled Worker
hashes, exact Git commit/tree, source hash and before/after file metadata.
Linked or nonregular source is not followed. Any content, inode or modification
metadata change during the gate makes its evidence stale, even if a file was
subsequently restored to its earlier bytes.

Outcomes are `passed`, `failed`, `skipped`, `unrunnable`, and `stale`. Nonzero
exit, timeout, cancellation, clipped logs, skipped/todo tests, Python expected
failures, zero tests, missing prerequisites and unclassified checkers cannot
be converted into a passing required gate. An interrupted or incomplete CI
setup gets an explicit unrunnable marker. CI logs and synthetic authentication
URLs are sanitized; no source service secrets or private data directories are
uploaded. Evidence expires after seven days to bound storage use.

For local inventory only:

```sh
node development/release-ci.mjs --inventory --output /absolute/path/outside-checkout
```

Full execution requires the configured pinned dependencies and the reviewed
clean commit. `--lane portable` selects portable suites; `--lane linux-root`
selects privileged synthetic fixtures; `--lane local-engine` selects workerd.
`--allow-dirty` is development-only: its results remain stale/non-releasable.
The integration owner performs the final complete gate once all contributing
changes are frozen. A local partial run or a prior-commit result cannot certify
a later merge or a production migration.

The workflow executes portable and local-engine lanes without elevated access.
Only the Linux-root lane uses sudo. The final combine step requires every
inventoried suite exactly once, all required lanes, matching clean source and
bundle identities, and successful individual results. Missing lanes, duplicate
suites or a positive lane summary hiding a failed suite cannot pass.

Hosted pull requests check out the requested head commit explicitly; the
workflow verifies it before discovery and uses it in the artifact name. The
event's synthetic merge commit remains a separate identifier. Privileged
fixtures read the same source inodes through a temporary read-only bind view
under `/tmp`, with matching dependency paths. This permits dropped-privilege
reads without opening the runner's private home directories. The view is
unmounted and removed on exit, and cleanup failure fails the step. Source and
before/after metadata comparisons still cover the original files. Linux secret
fixtures use private `/dev/shm` directories rather than assuming `/tmp` is RAM.
