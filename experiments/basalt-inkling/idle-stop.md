# Five-minute idle stop for the Basalt lab

These modules provide an optional supervisor integration. An integration can observe the five-minute countdown before attaching the provider stop capability.

## Observe the lab

Mount the file URL of `idle-native.mjs` at the **web profile root before agents, timers or tools accept work**. The required services are listed in its Cordis injection declaration. A supervisor adapter in that process obtains `ctx.get('basaltIdleActivity')`. Its `read(signal)` returns a random service-incarnation ID, an activity counter and a busy flag. Session reads use the passive rc.2 `sessionController.state({ sessionId }, signal)` API. An operator using `session/follow` for an independent check must set `activate: false`.

The observer covers the complete logical corpus, both inboxes, pending client inputs, the live agent phase (including between-turn maintenance), the tool execution waterfall, owned and unowned running/stopping jobs and outstanding PTYs. It reads cold inbox counts from the SDK's registered v1 projection at the exact session cursor. The first read of a cold history replays it in the Native process. The cache retains its count and cursor. Global session and job events and the start/end of tool execution change the activity counter even between polls. Out-of-band shell commands and other applications need their own admission and workload inventory before sharing this stop authority.

Construct `createLabObserver({ activity, readGeneration })` from `idle-guard.mjs`. Supply a fresh `readGeneration(signal)` returning a stable identity for **this exact contract**, kernel boot and both serving processes (for example instance ID, boot ID and supervised Native/Basalt PID plus process start ticks). Reject missing identities and unhealthy/loading services. The adapter reads the generation on both sides of the two service reads. It fetches live loopback Basalt metrics for the dedicated `inkling-2-mini` engine. It requires exact running/waiting gauges, all finish reasons and the generation-token counter. A declared completion family with zero generated tokens can still have no reason-labelled samples before the first request.

Construct `createIdleGuard({ observe, tryFence })` and call `tick()` every five seconds from one supervised owner. A new guard, boot, service incarnation, changed activity counter, busy result, unknown result or sampling gap over 15 seconds starts a fresh observation window. Five uninterrupted minutes of fresh idle measurements are required. The guard operates without a provider credential. With `tryFence` omitted, the most permissive result is `idle-without-fence`.

## Commit one stop

Start `native-idle-bridge.py` under the root service manager. Enable `BASALT_IDLE_BRIDGE=1` in the isolated Native environment, pass `--import /absolute/path/to/idle-preload.mjs` to Node before the web CLI entry, and insert the file URL of `idle-native.mjs` into the profile. Use the same verified release for these files. The preload targets the lab's HTTP/1 listener on port 8787. Native connects outward to the root-owned Unix socket `/run/basalt-idle-bridge/native.sock`. The broker checks Linux peer credentials, the exact Node executable and CLI entry, the real listener socket and its process start ticks. The root socket directory and the short recovery record belong in `/run`. Protect the installed control code against edits by project tools.

The supervisor opens `/run/basalt-lab-control/native-idle.sock`, sends one newline-delimited JSON request and reads one newline-delimited reply per connection. Only uid 0 may use this socket.

| Operation | Request |
| --- | --- |
| Read live activity, or the frozen proof | `{"op":"status"}` |
| Freeze this observed Native incarnation | `{"op":"freeze","epoch":"<status epoch>","revision":123,"lease":"<fresh UUID v4>"}` |
| Resume the same process | `{"op":"thaw","lease":"<same UUID v4>"}` |

A successful reply carries `ok:true`, `bootId`, `pid`, `startTicks` (decimal string), `epoch`, `revision`, `busy`, `frozen` and `lease`. Use the revision from the triggering live STATUS. Persist the lease UUID in the supervisor before sending FREEZE. Native closes its admission gate synchronously, verifies that no previously admitted operation is outstanding, takes another passive snapshot, rechecks the revision and writes the proof and signals itself with SIGSTOP in the same JavaScript turn. The broker confirms all threads in Linux stop state before publishing the frozen result. It retains the verified Native snapshot so the outer guard may still perform its final engine-plus-Native read while the process is stopped.

If FREEZE is refused, times out, or returns `ok:false`, retain the UUID and request THAW before another attempt. Reissue THAW with the same UUID if the broker or Native connection is reconnecting. The root broker uses a freshly verified pidfd for SIGCONT and requires the Native-side gate to acknowledge reopening. The THAW result conservatively reports busy until the next complete live STATUS. A restarted broker can verify an existing frozen proof from its root-owned same-boot record. An unconfirmed intent can only be recovered with THAW. A new boot discards the old Native lease. Provider-side stop ambiguity belongs to the supervisor's own durable attempt record.

Native gates physical HTTP, the rc.2 gateway's `dispatchRpc/openWireStream` calls from established WebSockets, in-process gateway calls and the SDK's work-creation methods. A known passive stream releases its hold after the first publication. Unknown streams and non-mux upgrade sockets hold the gate until they end; an interrupted, unconfirmed HTTP write keeps this generation awake. An idle connection to `/api/remote.mux` alone does not hold a lease. The synthetic SDK fixture opens that actual socket, reads a snapshot, checks that an activating frame on the same socket is refused with the gate closed, then reads again on the same connection after reopening.

The host adapter implements `tryFence(expectedGeneration, signal)` and returns either no lease or `{ reopen, commitStop }`. It must close **all** work admission for that generation, including mutating Native messages carried by existing WebSockets, scheduled internal producers and direct local engine requests. Already accepted requests must finish or remain visible to the final passive observation. A reverse proxy that closes only new connections leaves existing channels open. Scope each lease to one instance.

The guard reads Native and Basalt again while the lease is held and compares both counters and the generation. A changed or incomplete snapshot calls `reopen()` and restarts the five-minute window. When the final snapshot agrees, `commitStop()` must validate the lease, durably record one attempt for that boot and submit the stop for the configured lab instance only. Ownership of the closed gate then transfers to the supervisor. A lost provider acknowledgement keeps it closed until the owner reads the provider state and resolves that same attempt. The in-memory guard also refuses to resubmit. A supervisor restart must reconcile its persisted attempt before accepting work or creating a new guard.

## Operator verification

Before enabling the stop capability, verify the process identities, exact model and metric types, all ingress paths and the scope of the provider capability. Confirm in observation mode that a queued or parked turn, a foreground tool, a detached job, a PTY and a direct model request each prevent the idle decision. Check that a cold session with retained input remains cold and prevents sleep, that a brief request between polls resets the clock, and that a restarted supervisor receives the full five-minute grace. Then qualify a disposable fence with a concurrent submit over an existing WebSocket and directly to the engine. Each must either be rejected before acceptance or leave visible work which cancels the stop. Check a cold boot and a lost acknowledgement before enabling unattended provider calls.
