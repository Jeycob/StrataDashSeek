B10: Oprava existující aplikace

Vytvoř aplikaci v tomto čistém benchmarkovém projektu. Používej pouze syntetická data. Žádné reálné emaily, webhooky, platby ani externí účty. Dodrž specifikované rozhraní, protože výsledek ověří externí testy. UI musí být česky, přístupné klávesnicí, použitelné při 390x844 i 1440x900 bez horizontálního scrollu, s viditelnými chybami. Každý formulář musí mít programové labely a tlačítka s textem. Obsah vstupů vykresluj jako text, nikoli HTML. JSON API chyby vracej jako JSON se správným 4xx, nikdy neošetřenou 500. Data ulož trvale v projektovém prostoru, pokud scénář požaduje restart. API cesty i odkazy musí fungovat pod cestou uživatelského preview. Použij podporovaný Harness postup pro běžící službu nebo statické preview; na konci vrať skutečnou uživatelskou preview URL a stručný postup spuštění/restartu. Vzdálený localhost není doručené preview. Nepřepisuj externí přijímací testy. Testy modelu nejsou důkazem nezávislého přijetí. Maximální čas je uveden níže; po limitu bude běh ukončen. Nezakládej subagenty ani nové placené prostředky.

Časový limit hlavního běhu 600s; nejvýše jeden opravný běh 300s.

Oprav přiložený malý projekt fixture bez přepisování celé aplikace a bez dalších dependencies. Zachovej všechna původní API, funkce a původní testy. Tři známé chyby: (1) uživatel během pomalého save dál píše, odpověď staršího save nesmí přepsat novější draft; (2) hledání musí trimovat a ignorovat velikost písmen i českou diakritiku pro title/body; (3) PATCH /api/notes/:id musí atomicky vyžadovat baseVersion; stará verze vrací409 bez změny dat. Odpověď409 nesmí zahodit draft a UI musí nabídnout explicitní načtení novější serverové verze. Pro dva souběžné PATCH stejné baseVersion smí projít jen jeden. Uložení klient posílá {title,body,baseVersion}; server při úspěchu inkrementuje version právě1. testem používaný delayMs v PATCH (0..1000ms) zachovej jako syntetickou simulaci latence. Po změně vyhledávání i reloadu funguje editor. Zachovej přidání/smazání poznámek a persistence. UI labely „Název“, „Text“, „Hledat“; tlačítka „Uložit“, „Nová poznámka“, „Smazat“, při konfliktu „Načíst serverovou verzi“. data-testid="status" a data-testid="note-list" zachovej. Externí testy jsou mimo projekt. Zaregistruj funkční uživatelské preview.

Nezávislé UI přijetí:
1. Pomalé save500ms: po kliknutí během čekání dopsat text; novější draft zůstává, další save jej uloží.
2. q="  ZLUTY  " najde Žlutý kůň, q="PRILIS" najde Příliš…; prázdný filtr vrátí všechny.
3. Souběžný PATCH má jediného vítěze, konflikt v UI zachová draft a nabídne explicitní reload; původní CRUD a testy projdou.
